## 1. HOME launcher

- Akaa Flix was already a genuine HOME app (`MAIN` + `HOME` + `DEFAULT` intent filter, LEANBACK launcher
  entry). On firmwares that have **Default apps → Home app** (phones, AOSP Android TV) it is listed there.
- **Google TV (your Xiaomi TV Box) has no Home-app setting and no chooser.** That is a firmware decision; no
  app can add itself to a menu that does not exist. Monet and similar launchers solve this with an
  accessibility service, which v1.3 now implements (below). The Shizuku/ADB HOME-role method from v1.2 stays
  available as an alternative.

## 2. Home button service (real AccessibilityService)

| | |
|---|---|
| Where | Android Settings → Accessibility → Services → **Akaa Flix Launcher** (same place as Monet) |
| Activation | Manual, by the user: Enable → Android's warning → OK. Akaa Flix opens the screen and explains the steps; it never turns the service on by itself. Optional **Turn on with Shizuku** runs the same command as ADB, keeping every other enabled service (e.g. Xiaomi's TvService) |
| Status in Akaa Flix | Settings → Interface settings → Home app & start-up → *Home button service*: **On / Off / On – not running**, read from Android (`enabled_accessibility_services` + whether Android bound the service). Also in Diagnostics |
| Home key | While Android would open another launcher, the Home key is taken and Akaa Flix opens (on release). When Akaa Flix is Android's real default Home, the service leaves the key to Android. All other keys pass through untouched |
| Another launcher appears | If Google TV's Home screen opens anyway (voice command, an app, boot), Akaa Flix is brought back. Only the launcher's Home activity triggers this – its search/settings screens and popups are left alone |
| Start-up after reboot | Android binds the service after every restart; its first connection after a restart opens Akaa Flix. The start-up row says "Verified: the Home button service opened Akaa Flix m:ss after the last restart" **only** when this was observed |
| Access requested | `typeWindowStateChanged` (package/class name of new windows) and key filtering. **No** window content (`canRetrieveWindowContent=false`), no gestures, no screenshots, no network. Android's warning ("can collect all text you type…") is generic for every accessibility service |
| Restricted settings | Android 13+ can grey out the switch for apps installed from a file. Akaa Flix shows how to allow it; on TV (no ⋮ menu) use `adb shell appops set --user 0 com.akaaflix.launcher ACCESS_RESTRICTED_SETTINGS allow` or the Shizuku button |

## 3. Shizuku

- Official Shizuku API 13.1.5 (unchanged dependency). Authorization only through Shizuku's own dialog.
- **Connection detection is now live**: Shizuku's binder-received / binder-dead / permission listeners update
  the App manager immediately. When Shizuku stops (or the box restarts) the page says "Shizuku stopped…" and
  the row shows *Not running*; privileged actions fall back to the App info screen / ADB command.
- **Reconnection**: *Open Shizuku* and *Check again* buttons; when Shizuku runs again, "Shizuku connected" and
  the actions are available again (permission is requested if needed). A dead shell process is rebound on the
  next command.
- Actions for user 0: disable / enable (`pm disable-user` / `pm enable`), **uninstall user apps directly**
  (`pm uninstall --user 0`, new in v1.3, with a "cannot be undone" warning), remove pre-installed apps for
  user 0 (`pm uninstall -k --user 0`, restorable with `pm install-existing`), uninstall updates. Critical
  system packages stay information-only. No root is requested, nothing is simulated.

## 4. Bug fixes found while doing this

- Option dialogs (e.g. the App manager package dialog in your photo): rows scrolled out of view were drawn
  over the dialog title ("Mi Channel" over "Category"). Rows are now clipped at the list edge; nothing else in
  the dialog changed.
- A delayed layout callback could touch the Home page after the activity was recreated (language/font
  change) and crash; it now checks that the page is still attached.

## 5. What works without anything extra / what needs more

| Feature | Requirement |
|---|---|
| Home button + start-up on Google TV | The Home button service, turned on once by the user (no ADB needed unless Android shows "restricted setting") |
| Becoming Android's real default Home on Google TV | Shizuku or ADB (HOME role); may still be overridden by Google TV on some builds |
| Disable / remove pre-installed apps, silent uninstall | Shizuku (started by the user; restart it after every reboot without root) or ADB |
| Everything else | Nothing extra |

## 6. Android system limitations (honest list)

- The accessibility service reacts after Android delivers events. At start-up Google TV's Home can be visible
  for a moment before Akaa Flix comes to the front.
- While the service handles the Home key, **long-pressing Home also opens Akaa Flix** (Google TV's long-press
  panel is not reachable through the key; its settings stay reachable from Akaa Flix's settings).
- Android can stop accessibility services (crash, "force stop"). The status then shows *On – not running* and
  explains how to restart it.
- **Google Play Protect**: an accessibility service is one of the capabilities Play Protect looks at for
  sideloaded apps. In regions with *enhanced fraud protection* a sideloaded APK that declares one can be
  blocked or warned about at install. v1.0.1 removed such capabilities to avoid exactly this; v1.3 adds the
  service back because you asked for it. Nothing in the APK hides or disguises it (see SECURITY_AUDIT.md §13).
- Shizuku without root must be started again after every reboot.
